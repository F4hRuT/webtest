# Лаймо — мобильный сайт банка (webtest)

Сайт: https://f4hrut.github.io/webtest/ (GitHub Pages, ветка `main`, корень репозитория).
Соседний репозиторий `../iOS-menu` — исходное оранжевое меню, из которого сделано меню банка.

## Правила работы (обязательно)

1. **Сначала проверяю сам, потом сдаю.** Пользователь не тестировщик. Готовую версию отдаю только после проверки
   в симуляторе iPhone (Safari iOS), со снимками «образец / результат». Если что-то не проверил — прямо так и пишу.
   Safari на Mac и сверку с опубликованным сайтом делаю **только по просьбе** — опубликованный результат пользователь
   смотрит сам на своём телефоне (экономия токенов). Снимки — только нужного куска (меню, изменённый блок), не всей страницы.
2. **Коммиты — на русском**, коротко и по делу: что сделано и зачем.
3. **Версия:** при каждом изменении увеличиваю номер в подвале `index.html` («Версия N») и параметр `?v=N` у `menu.js`
   в `<script src="menu.js?v=N">` в конце `index.html` (иначе браузеры берут старое меню из кэша). Ссылка для пользователя: `https://f4hrut.github.io/webtest/?v=N`.
4. **Зафиксированное не трогаю** (раздел ниже), если пользователь прямо не попросил.
5. Одна задача — одно изменение. Не «улучшаю» попутно то, о чём не просили.

## Структура

- `index.html` — вся страница банка (CSS + JS внутри). Экраны: Главная, Тариф, Расходы, Поддержка.
  Мягкие углы блоков — SVG-фон по алгоритму figma-squircle (`sq()`, сглаживание 0.8), не clip-path.
- `menu.js` (с v95) — меню (таб-бар) со стеклом: стили, разметка и код меню (бывший `menu.html`, копия `../iOS-menu/index.html`
  с изменениями ниже) + модуль стекла `GLS`. Меню живёт прямо в странице: `<div class="dock" id="dock">` + `<script src="menu.js?v=N">`.
  Связь: страница задаёт `window.ITBH={sel(i),ready()}`, меню даёт `window.ITB.set(i)`. Пока меню не готово, `#dock` скрыт.
  Стили меню — под `#dock`, id — с приставкой `itb-`, панель — класс `.tbar` (у страницы есть свой `.bar`).
  Выключить стекло для проверки: `?itbglass=0` (тогда меню ровно как v94 — проверено до пикселя).
- `test/glass.html` — тестовая страница для сверки стекла с iOS (см. «Инструменты»). `tools/glass-app/` — тестовое приложение iOS,
  `tools/glass-analysis/` — скрипты замеров (в них путь `S` к папке-черновику — поменять на новый).

## Зафиксированный вид меню (v93) — не менять без просьбы

Эталон — таб-бар iOS 27 в приложениях «Фитнес» и Watch на симуляторе (у обоих одинаковые заливка, обводка и капсула), снятый
над чёрным фоном. Совпадение v93 на тестовой странице: ~89% пикселей точно, ~98.5% — не больше 1 ступени яркости
(на странице сайта 85% / 97.5%: под меню не чёрный фон, а затемнённая страница).
- **Бар:** 360 × 62 pt. Контур — та же кривая, что `path()`, но переход к прямой подобран под iOS: угол 56°, длина 2.1R
  (`BPHI`, `BARAT`). Рисуется функцией `bpath()` из коротких кривых. Совпадение контура с iOS ±0.2 px.
- **Заливка:** сплошная 28 (`FILLV`) + слабое пятно 29 снизу посередине (`BLOBV`, `blob()`), как у iOS.
- **Обводка и свечение:** 20 векторных линий по 1/3 pt, по одной на каждый пиксель от края (`ROWS`: цвет сверху посередине
  и прозрачность по углу края `ANG`), к бокам гаснут до нуля. Яркость по пикселям в 3x посередине верха и низа:
  **86 → 69 → 56 → 39**, дальше 37, 36, 34, 33, 33, 32, 31, 31, 30, 30, 30, 29…, середина 28.
- **Край:** кольцо 1/3 pt цвета заливки (`bpath`), слой заливки обрезан на 1/6 pt глубже — край сглажен, ступеньки clip-path закрыты.
- **Капсула активной вкладки:** `#070707`, 95 × 54 pt, 4 pt от края бара, форма `path()` (52.4°, 1.889R) — совпадает с iOS.
- **Вкладки:** центры 51.5 + 85.67·i pt (`CX0`, `PITCH`); иконки сдвинуты вместе со вкладками, сами иконки прежние.
- **Активная вкладка:** салатовый `#b6d70a`, остальные иконки и подписи белые.
- **Положение:** блок `#dock` 80 px, `bottom: env(safe-area-inset-bottom) + 5px`, бар прижат к его низу с отступом 3 px.
- **Под меню:** затемнение страницы `.fade` высотой 72 px (от уровня верха меню) с размытием в два слоя + чёрная полоса `.edgefill` 4 px у самого низа.
- **Появление:** пружинное (масштаб 0.84 → 1 с перелётом, ~0.8 с), до готовности меню скрыто.
- Старая подсветка обводки от цветных объектов (до v92) **удалена по просьбе пользователя** — не возвращать её.
  Новая окраска меню и обводки по фону делается только в задаче «Жидкое стекло» (раздел ниже) — строго по замерам iOS.
- **Вспышка при нажатии** `.fl` лежит над SVG-обводкой (v94), обрезана маской по контуру `bpath`.

## Что уже выяснено (не наступать снова)

- **Мыло в Safari:** canvas в iframe Safari иногда выводит в низком качестве. Лечится в `menu.js`: canvas не пересоздаётся
  без изменения размера, позиция бара округляется до пикселя устройства (`snap()`), после загрузки и после каждой анимации —
  принудительная перерисовка (`recomp()`). Не убирать.
- **Ступеньки на скруглениях:** `clip-path` в Safari рисует край без сглаживания. Край должен закрывать SVG-обводка, лежащая
  поверх обрезанного слоя (как в iOS-menu). Не рисовать обводку растровой картинкой и не выносить фон в отдельный слой.
- **Белая полоса под панелью Safari (iOS 26+):** Safari красит область своей панели в цвет `position:fixed` элемента, который ближе 3 px
  к низу экрана и шире 80% экрана. Поэтому iframe меню стоит на 5 px выше края, а у края — чёрная `.edgefill`.
- **Старые телефоны (Redmi 9A/9C, Galaxy A12, старые Chrome/Яндекс/Mi Browser):** код меню на ES5, фолбэки: mask вместо clip-path,
  `basic()`-режим без Path2D, touch/mouse без PointerEvent, автоснижение качества `Q` (lite) при медленных кадрах. Не ломать.
- `will-change: transform` на баре в iframe давал мыло — снимается в `snap()`.
- **Safari спрямляет длинные пологие кривые** (ломаная проваливается внутрь до 0.25 px) — на переходе скругления к прямой
  гасла яркая строка обводки. Поэтому контур бара — `bpath()` из коротких кривых. Не заменять на одну кривую.
- **Порядок линий обводки:** от внутренних к внешним (яркая внешняя сверху), иначе на изгибах проступают тёмные внутренние.
- **Градиенты в Safari дают шум ±1** по цветам — заливку делать сплошным цветом, градиент только там, где нужен.
- **Меню iOS слегка просвечивает** то, что под ним, — эталон снимать над чёрным фоном
  («Фитнес»: вкладка Summary, прокрученная до конца; Watch — первый экран).
- **Всё, что лежит над обводкой, должно её освещать:** в v93 вспышка `.fl` была под непрозрачными линиями обводки, и при
  переключении внутри меню проступал тёмный прямоугольник (исправлено в v94). Новые слои меню проверять во время нажатия (видео).
- **Снимок страницы для стекла (SVG foreignObject) в Safari:** читать его в canvas/WebGL можно (не «грязный»). Но:
  (1) масштаб через `viewBox` Safari не применяет к содержимому — увеличивать только CSS `transform:scale()` внутри;
  (2) картинки внутри снимка (в т.ч. SVG-фоны карточек `sq()`) догружаются после `onload` — снимок заливается повторно
  через 250 и 700 мс; (3) внешние файлы-картинки в снимок не попадают вовсе — только data URL; (4) снимок выше
  `MAX_TEXTURE_SIZE` (4096 на старых) не загрузится — разрешение снижается; (5) `vh` внутри снимка = высота снимка.
- **Прокрутка в Safari:** положение прокрутки приходит в скрипт на ~2 кадра позже, чем двигается страница, — стекло
  отставало на 15 pt при быстрой прокрутке. Лечится предсказанием по скорости (`LAT` 32 мс в `menu.js`). При прокрутке
  Safari сворачивает нижнюю панель и меню съезжает на ~40 pt вниз — положение бара брать каждый кадр.
- **Известный старый дефект:** при переключении у края «линзы» капсулы мелькают салатовые кусочки соседних иконок
  (линза берёт их из зелёной текстуры `texO` вместо белой). Было и в v92. Исправить в задаче «Жидкое стекло».

## Следующая задача: «Жидкое стекло» в меню (план утверждён пользователем)

**Цель (слова пользователя):** меню должно выглядеть и вести себя **точно как у Apple** — идентичный iOS внешний вид меню
и обводки плюс эффект жидкого стекла у самого меню. Меню как таб-бар iOS 27: просвечивает размытое содержимое под ним,
светлеет и окрашивается от цвета под ним **локально** (зеленеет над зелёным, светлеет над серым — даже над тёмно-серым
блоком вместо чёрного уже чуть светлее), обводка светлеет и окрашивается пропорционально, там, где под ней цветное,
у краёв содержимое слегка изгибается (преломление) при прокрутке страницы. При этом **рисунок обводки не меняется**:
её толщина, переходы яркости от края внутрь и затухание к бокам остаются как в v93 — меняются только значения цвета,
плюс добавляются стекло и размытие. **Над чёрным фоном — ровно v93.** Анимации переключения и иконки не менять.

**Видео-образец пользователя** (реальный iPhone, iOS 27.0.1, «Фитнес» → вкладка «Тренировка», прокрутка, 58 с):
`reference/ios-fitness-workout-scroll.mov` и кадры `reference/frame_0s.png`, `frame_12.5s.png`, `frame_15s.png`,
`frame_35s.png`, `frame_52.5s.png`. Папка `reference/` только на Mac (в `.gitignore`, на GitHub не публикуется).
Видео сжатое — по нему понимать поведение, а числа брать с симулятора. Замеры по кадрам (центр меню, x = 360 px):
- 0 с, над чёрным: обводка сверху 84 → 64 → 55 → 34, середина 27 — как v93;
- 15 с, над серой карточкой: середина 52 (было 28), обводка 89 → 71 → 59 → 41 — светлее на 3–5, рисунок тот же;
- 35 с, над зелёной карточкой: середина (50, 55, 42), обводка (91, 96, 79) → (72, 77, 62) → (59, 64, 49) — зеленеет;
- 52.5 с: зелёное только под нижней частью — зеленеет и светлеет только низ меню (обводка снизу 102 вместо 86);
- 12.5 с: белая надпись Fitness+ под верхним краем — край меню светится 123–129, надпись просвечивает размытой и растянутой.

**Способ:** своё тестовое приложение iOS с настоящим системным таб-баром (`tools/glass-app/main.swift`): показывает под меню
любую картинку/прямоугольники по файлу `Documents/spec.json` (опции: `icons:false` прячет иконки, `tab` — выбранная вкладка,
`scroll`, `anim` — сдвиг/прыжок). Снимок → таблицы → формулы. Кода Apple не копируем.

### Этап 1 — СДЕЛАН (v95, 21.10.2026)

**Замеры iOS 27 (симулятор, 3x; данные — `reference/glass-data/*.npz`, только на Mac).** Модель меню: каждая точка бара =
`A + K·G`, где `G` — цвет «стекла» в этой точке, `A,K` — свои у каждого пикселя (над чёрным `G=29` → вид v93):
- **Цепочка стекла:** картинка под меню → размытие (в sRGB^0.932) → изгиб (сдвиг выборки) → кривая яркости и насыщенность.
- **Что видит стекло:** только прямоугольник «бар + 16 pt» (x 5..397, y 775..868.7 pt); дальше — край повторяется
  (clamp), то, что дальше 16 pt от меню, на стекло **не влияет совсем**.
- **Размытие** (одинаковое по x и y, не зависит от места): 5.3% почти чёткая копия (σ 0.22 pt) + 94.7% ×
  [75.5% гаусс σ 13.26 pt + 24.5% гаусс σ 25.7 pt]. Делается над значениями `(цвет/255)^0.932`.
- **Кривая яркости** g(L), L = 0.2126R+0.7152G+0.0722B (sRGB 0–255): L 0→29, 8→34, 16→39, 32→48, 64→66, 96→82, 128→95,
  160→106, 192→116, 224→123, 255→128 (полная таблица 256 — `LUT` в `menu.js`). Ошибка ≤0.5.
- **Цвет:** `G = g(L) + r(L)·(c − L)`, r(L) = 0.85 − 0.00092·L (0.84 у тёмных → 0.63 у ярких). Точность ±3, хуже всего
  синий (iOS насыщеннее на ~9). Светлого режима над белым нет (тёмная тема).
- **Чёткая составляющая:** над светлым фоном у iOS текст под стеклом виден примерно вдвое сильнее, чем даёт 5.3% —
  похоже, детали добавляются уже после кривой. Уточнить на этапе 2.
- **Изгиб** (сдвиг выборки по нормали к краю, t — пиксели 3x от края, «+» = внутрь, к центру; сверху/снизу и в
  закруглениях одинаково с точностью ~0.5 pt): t 0 → −25.7 (берёт с 8.6 pt снаружи), 1 → −10.7, 2 → +1.3, 3 → +6.4,
  4 → +6.3, 6 → +5.5, 8 → +4.4, 12 → +3.9, 15 → +3.3, 20 → +2.6, 25 → +1.7, 30 → +1.1, 36 → +0.6, 60 → 0.
  То есть внешние 2/3 pt кромки «заглядывают» наружу, а полоса ~15 pt внутри слегка увеличивает картинку. Снизу внутрь
  сильнее (до −7 px против +6). Подробная карта — `disp_t1.npz`.
- **Обводка над цветом:** `out = A + Kl·L(G) + Kc·(G − L(G))`: ряд 0 (кромка) A 62.5, Kl 0.85, Kc 1.29; ряд 1 — 44.2/0.89/1.20;
  ряды 3–7 — Kl ≈0.97, Kc ≈1.03; внутри 0/1/1. То есть кромка светлеет на 85–97% от стекла и насыщеннее его.
- **Капсула выбранной вкладки:** K 0.872, `out ≈ 0.872·G − 18.3` (над белым 93); у неё своя линза (сдвиг ~+3 pt у её края).
- **Тень:** под меню на белом −3 ступени, 3–4 pt вниз (сверху и по бокам нет).
- **Время:** стекло меняется в том же кадре, что и фон, без плавного перехода. Затемнение у края экрана iOS (scroll edge
  effect) картинку под меню не меняет.

**Что сделано на сайте (v95):** меню перенесено из iframe в страницу (`menu.js`). Под ним — WebGL-холст: снимок страницы
(`#app` через SVG foreignObject, со стилями страницы, анимации остановлены в конечном виде) → вырез «бар+16 pt» (сетка 2 pt) →
размытие двумя проходами → кривая g + цвет r(L) + 5.3% чёткой копии. Холст рисует заливку 28, пятно 29 и сглаженный край
(маска по `bpath`); линии обводки v93 остались векторными, но складываются со стеклом (`mix-blend-mode: plus-lighter`,
цвет линии − 28) — над чёрным это ровно v93, над цветом обводка светлеет вместе со стеклом (пока с K=1, без Kc).
Снимок обновляется при любом изменении `#app` (через 150 мс) и при смене размера.

**Сверка этапа 1** (`tools/glass-analysis/cmp_blur.py`, наше меню на `test/glass.html` против iOS, одинаковые картинки):
- над чёрным: 86% пикселей точно, 96.6% ±1 (v94: 88% / 96%) — разница только в округлении;
- граница чёрное/белое, глубже 1.3 pt от края: средняя ошибка 1.0–1.3 ступени, 95% точек ≤3; ровные цвета ≤1–2 (синий/красный до 4);
- полоски и пёстрая картинка: 2.6–4 (95% ≤6) — из-за чёткой составляющей; кромка (внешние 1.3 pt): 4–14 — нет изгиба и Kc;
- снимок страницы против настоящего экрана: после размытия расхождение 0.3 ступени (95% ≤2);
- прокрутка: с предсказанием прокрутки стекло идёт вровень со страницей (±2 pt при 1500 px/с; без него отставало на 2 кадра).

## Проверка перед сдачей

- **VPN не выключать.** Пользователю он нужен: без VPN не работает Claude Code. С включённым VPN симулятор
  не открывает сайты из интернета («не удаётся найти сервер»), но адрес `localhost` открывает. Сам Mac (curl) сайт в интернете
  открывает и с VPN. Поэтому порядок такой:
  1. Запустить локальный сервер в папке проекта: `python3 -m http.server 8000`. Проверить в симуляторе `http://localhost:8000/?v=N`.
  2. Если всё в порядке — коммит, `git push`, подождать сборку GitHub Pages (`gh run list`).
     Дать пользователю ссылку `https://f4hrut.github.io/webtest/?v=N` и напомнить: внизу страницы должно быть «Версия N»,
     если номер старый — подождать 1–2 минуты и обновить страницу.
  3. **Только по просьбе:** сверить опубликованные файлы с локальными байт в байт (с Mac, при включённом VPN):
     ```
     for f in index.html menu.js; do curl -s "https://f4hrut.github.io/webtest/$f?nocache=$RANDOM" | cmp -s - "$f" && echo "$f совпадает" || echo "$f ОТЛИЧАЕТСЯ"; done
     ```
     Всё совпадает — значит в интернете ровно то, что проверено в симуляторе. Если отличается — подождать 1–2 минуты и повторить.
- **Safari iOS:** симулятор «iPhone 17 Pro», iOS 27.0.
  ```
  xcrun simctl boot "iPhone 17 Pro"            # если ещё не запущен
  xcrun simctl openurl booted "http://localhost:8000/?v=N"
  xcrun simctl io booted screenshot /tmp/sim.png
  ```
  Окно симулятора: Xcode → Open Developer Tool → Device Hub. Для нажатий/жестов — MCP `ios-simulator` (idb).
- **Safari на Mac (только по просьбе):** управлять через WebDriver: `safaridriver -p 4446` в фоне, затем сеанс `POST /session`.
  Автоматизация разрешена (в Safari: «Разрешить удалённую автоматизацию» + `safaridriver --enable` с паролем пользователя;
  эта команда падает с «segmentation fault», но разрешение сохраняется). Экран Mac — 2x, яркость обводки отличается от чисел 3x — это нормально.
- **WebKit и Chrome:** MCP `playwright` (WebKit); для Android — эмуляция ширины 360 и 390, DPR 2–3.
- **Сравнение с образцом:** ImageMagick (`magick compare -metric AE …`), ffmpeg — для покадрового разбора видео.
  Образцы от пользователя — PNG 3x с iPhone.
- **Публикация:** `git push` в `main`, GitHub Pages обновляется 1–2 минуты (статус: `gh run list`). Пользователю давать ссылку с новым `?v=`.
