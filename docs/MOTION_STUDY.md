# Исследование движения капсулы — в работе

Состояние на 09.11.2026. Сайт остаётся **v123**, код приложения ещё не менялся. Эта запись — контрольная точка исследования, а не отчёт о готовой точной копии.

## Задание и эталон

Пользователь просит воспроизвести переключение вкладок iOS: траекторию, физику, изменение размеров/вида/теней, удержание, отпускание и прерывания. Требуется цикл эталон → код → PNG/видео Safari → численная сверка → повторная правка → публикация с номером версии. Если захват/проверка не работают — запросить ручную помощь коротким опросом, не объявлять работу завершённой.

Пользователь вернул физический iPhone в **тонированный** режим Liquid Glass. Более ранняя запись о прозрачном режиме — история. Не менять настройки телефона автоматически.

Текущий эталон: системный UITabBar в Glass на виртуальном iPhone 17 Pro / iOS 27.0, чёрный фон, подписи «Главная / Тариф / Расходы / Поддержка», символы house / chart.bar / wallet.bifold / ellipsis.message. Физический iPhone — iOS 27.0.1. Разницу версий учитывать при финальной проверке.

## Что действительно проверено

- Через Mac-приложение **Device Hub** выполнены короткие нажатия ~80–90 мс, переход через одну вкладку и удержание ~600 мс. Native и сайт записаны отдельно в исходном размере 1206×2622.
- Рабочий путь к приложению: /Applications/Xcode.app/Contents/Applications/DeviceHub.app. Пользователю называть его Device Hub. Пункт Xcode → Open Developer Tool → Device Hub.
- Виртуальный iPhone выбран в верхней строке боковой панели; физический — отдельная нижняя строка. С 09.11.2026 автоматический тестовый ввод разрешён пользователем в четырёх разрешённых экранах.
- Записан покадровый журнал собственных тестовых сборок через CADisplayLink: bounds/position/transform, opacity, shadow и касания. Системное меню меняет и позицию, и масштаб по обеим осям, и размеры линзы; эти процессы нельзя свести к одной скорости.
- В журнале bounds нативной линзы высота при удержании достигает 70 pt против исходных 54. Видео показывает выход стеклянной капсулы за панель. В v123 paint ограничивает высоту HMAX=60, а движущуюся капсулу дополнительно зажимает внутри BW. Это существенный кандидат для исправления, но bounds отдельного слоя не равны видимому контуру.
- Получен журнал тех же входов Safari с performance.now(), L/R, высотой, прозрачностью линзы, вспышкой и масштабом панели. Текущие фазы движения и высоты отличаются от native; старая скорость SPEED=1.55 влияет также на общий clock. Не менять её вслепую: она затрагивает иконки и другие каналы.

## Неудачные подходы и ограничения

- idb ui tap на виртуальном iPhone не доставляет события: ошибка remote.hid.digitizer. Работал ввод через CUA в Device Hub.
- В первой тестовой сцене spec.json содержал tab:0. Каждый лениво загружаемый Scene применял его и возвращал выделение на первую вкладку. Для пользовательских переключений **убрать tab** из сцены. Это ошибка стенда, не системная физика.
- Во время анимации UIKit перестраивает дерево слоёв. Числовые пути слоёв меняются; находить нужные по классу и проверять родительскую систему координат. В экспериментальных глобальных rect обнаружены скачки на ширину отступа панели (21 pt). Эти rect нельзя использовать как готовый эталон или молча «лечить» вычитанием константы. Добавлено независимое чтение modelRect/modelBounds/modelMatrix и времени обработки касаний; контрольные входы после этого ещё не завершены.
- Полученные анимации CALayer не раскрыли конечные CASpringAnimation с mass/stiffness/damping. Числа, подобранные аналитически по журналу, — приближение, не извлечённые параметры Apple.
- В simctl-видео native обнаружены повторные/немонотонные временные метки при декодировании FFmpeg. Видеокадры пригодны для осмотра формы, но такие фрагменты нельзя считать надёжным измерением длительности или каждого кадра 120 Hz. CADisplayLink и touch timestamp также нужно сверять с фактическим временем обработки и изображением.
- В одном прогоне CADisplayLink фактически выдавал около 60 Гц несмотря на запрос preferred=120. Не выдавать запрос 120 за подтверждённые 120 уникальных кадров.
- Прямой devicectl screen-record физический телефон не поддерживает. AVFoundation после включения screen-capture discovery не показал muxed USB-экран iPhone; камеры не открывались. QuickTime настроен, но полученный поток оказался устаревшим: 63 с без движения при реальных переключениях. Он не подходит для измерения. Рабочая замена — DisplayService/RTP, см. ниже.
- CUA однажды читал окно/скрин Device Hub, но ввод трижды вернул noWindowsAvailable. Получение приложения и AX Raise не помогли. Пользователь вручную вывел окно на передний план; после этого нажатия снова заработали и контрольные переходы записаны. Не считать эту ошибку отказом самого iPhone.

## Измеритель

tools/validation/glass_motion_probe.swift — экспериментальный код только для собственной сборки Glass **на виртуальном устройстве**. Использует публичные UIKit/CALayer API; имена внутренних классов только читаются для фильтрации, приватные методы не вызываются. Не добавлять его в сайт и не устанавливать на физический телефон.

Для отдельной временной сборки из tools/glass-app/main.swift:
1. Заменить создание UIWindow(windowScene: ws) на ProbeWindow(windowScene: ws).
2. После window = w добавить MotionProbe.start(w).
3. Компилировать оба Swift-файла SDK iphonesimulator и target текущего runtime. В этой среде успешно: arm64-apple-ios27.0-simulator, Xcode 27.1.
4. Отдельный bundle id, например local.test.glass.motionprobe; не заменять установленный физический Glass.
5. spec.json в Documents: {"id":801,"bg":[0,0,0],"icons":true,"scroll":false,"titles":["Главная","Тариф","Расходы","Поддержка"],"symbols":["house","chart.bar","wallet.bifold","ellipsis.message"]}.
6. Запускать только на известном виртуальном UDID. Снимать ограниченный по времени сценарий. Журналы probe-*.json пишутся раз в секунду в Documents собственного приложения; после замера приложение остановить.
7. После simctl install заново получать get_app_container: UUID папки меняется. Не читать устаревший путь.
8. Пустые CGPath и бесконечные duration требуют очистки перед JSON: иначе NSJSONSerialization бросает ObjC exception, try? его не перехватывает. Измеритель уже превращает нечисловые значения в строки.
9. Это вспомогательная телеметрия. Нужна независимая сверка видимого контура по PNG/кадрам. Снятие телеметрии может влиять на время кадров.

Последняя версия измерителя компилируется, запускается и проверена тремя переходами после восстановления ввода. Теперь обход начинается от ЕДИНОГО tab.layer.presentation() и рекурсивно идёт по его sublayers; каждому узлу соответствует model() только для имён/модельных данных. Прежнее смешивание поддеревьев разных коммитов приводило к ложным скачкам 21 pt. В новом журнале таких скачков для проверенных переходов нет.

fixtures/native-motion-samples.json содержит обезличенные измерения трёх переходов: соседний (~97 мс), через вкладку (~99 мс), обратный через три с удержанием ~3,016 с. Время display_t = CADisplayLink.timestamp − время обработки touch down, callback_t = CACurrentMediaTime − то же начало. Это разные моменты; не смешивать. cx_bar/width_bar/height_bar приведены обратно в координаты панели до её масштаба. В покое ширина 99,333 и высота 54 pt; при длинном удержании целевой размер линзы 115,333×70, динамическая высота видимого слоя в журнале до ~80,94 pt, масштаб панели до 1,0424. Это геометрия слоёв, ещё не независимая попиксельная оценка стекла.

Модельные значения слоя сразу становятся конечной целью; они не показывают траекторию. В прогретых коротких входах модельный переход обратно на малый размер начинается примерно через 0,23 с от обработки down, несмотря на up около 0,10 с. При длинном удержании — после up. Реакцию на нажатие/отпускание нужно отделять от движения между вкладками.

fit_recorded_springs.py позволяет воспроизводимо подбирать кандидат пружины центра к этому fixture (numpy/scipy). На сохранённом наборе получено w≈15,770 рад/с, ζ≈0,8469, нормированный RMS≈0,00647. Первый холодный вход с задержкой отличается от прогретых. Это приближённая регрессия для исследования, НЕ параметры Apple и НЕ доказательство точного совпадения. На другом контрольном прогоне модельного журнала получалась существенно меньшая ошибка; её не переносить на fixture/сайт.

## Физическая запись 09.11.2026

Автоматический тестовый ввод явно разрешён пользователем; ограничения остальных приложений/настроек сохраняются. Ввод и живой экран работают через CUA по canvas localhost viewer pymobiledevice3==11.50.2, userspace tunnel. Не менять стиль/доступность/clipboard и не использовать системные кнопки viewer. Кнопки Device Hub physical View Screen не передавали касания; новый HID-канал передаёт.

tools/validation/ios_motion_capture.py запускает loopback viewer и сохраняет исходный video RTP без перекодирования/аудио. Параметры: --udid DEVICE --output TEMP --port 8765 --limit 90. Требуется существующее доверенное сопряжение; autopair и fallback отключены. В TEMP/control.json записать {"id":UNIQUE,"action":"start","label":"slug"}, затем новый id/action stop. Запись ограничена 1–120 с. Остановить процесс после замеров. Ничего не устанавливает на телефон и не меняет его настройки.

Холодное открытие HID раньше сводило первый down/up к <1 мс. Текущий адаптер предварительно открывает HID до сценария и после восстановления stream, без создания дублирующего worker. Проверять dispatch_begin/end в metadata: requested duration не доказательство actual duration.

tools/validation/decode_motion_rtp.py SOURCE.rtpbin --output RESULT.h265 извлекает HEVC AU и RESULT.frames.json с исходными RTP timestamp, host monotonic receive и packet gap статистикой. После потери пакета повреждённый AU и зависимые кадры до ключевого отбрасываются. Annex-B сам по себе не содержит временной шкалы: нельзя доверять синтетическому fps FFmpeg. Источник около 24000 ticks/s, типичный шаг 400, около 60 fps, встречаются более длинные интервалы. Потоки без packet gaps всё равно могут пропускать обновления дисплея. Кодек Main 8-bit full-range 4:2:0, 1216×2656 с padding; активное изображение 1206×2622. HEVC lossy — только динамическая геометрия, не доказательство точных статических кромок.

Итоговые физические серии (локально, не выгружены):
- short-final: начальная вкладка 1, цели [2,0,3,1,0,1], 95–99 мс, 2646 кадров.
- holds-final: те же переходы, 1,206–1,209 с, 3270 кадров.
- gestures-final: same-tab hold 1, drag 1→3→0→2, cancel вверх, rapid [0,3,1,2], 2943 кадра.
- fitness-final: Fitness+ / Тренировка / Поделиться, короткие и длинные касания, 1609 кадров.
Во всех четырёх сериях packet gaps=0, dropped AU=0; первые pre-key кадры short/holds пропущены (1/1). Отдельный первоначальный hold-check пригоден для визуального контакта, но основной набор — final.

Нативный Glass сохраняет отдельную позицию прокрутки каждой сцены. Для материала сначала выровнять фон, не смешивать фоновую смену с изменением стекла. Видимый выход капсулы за панель подтверждён; до замера контура не считать bounds слоёв точными размерами видимого стекла. Подложка v107 в Glass — старый снимок сайта, не текущая версия приложения. Host dispatch и получение RTP включают транспортную задержку: синхронизировать начало по изображению, не добавлять её сайту.

## Первая реализация для физической проверки

В test/dev/motion-v124.html опубликован отдельный preview; корневые index.html/menu.js пока v123. Реальная временная шкала капсулы отделена от старого clock иконок SPEED=1.55. Центр — непрерывная пружина ω15.83/ζ.853, давление bounds +16 pt по осям — ω10.645/ζ.8606 down и ω24.383/ζ.9745 up с минимальной фазой .23 с. Оптика имеет отдельную пружину; масштаб панели .039. Кривые деформации нормированы на текущие bounds (иначе длинный hold и short release давали разную ошибку высоты). Stage больше не отрезает выходящую капсулу; запас canvas 22 pt; стартовый буфер прогрет до 150×90 pt. Это приближённая реализация по замерам, не извлечённые параметры Apple.

Локальная UI-проверка нажатий/hold/drag прошла без error/warn в консоли. CUA desktop доставлял длинные интервалы вместо requested 90 мс; для точного времени использовать физический HID metadata и RAF-лог. Математическая сверка compare_motion_model.cjs по исходному fixture даёт RMS центр/ширина/высота примерно .14–.95/.29–.72/.16–.59 pt; по независимым long1/long2/short3: до 1.22/2.30/1.83 pt (холодный long1 отличается по фазе). Эти цифры только геометрия слоёв, не рендер Safari и не доказательство идеальной копии.

## Физическая сверка r1 и вторая итерация

Safari: те же шесть short/hold и drag/cancel/rapid, 1843/2076/1960 декодированных кадров, packet gaps/dropped AU=0, short 97–107 мс, hold ~1,21 с. JS/resource errors=0, glass on.

Третий длинный переход 0→3 над чёрным: центр панели определён отдельно; вершина кромки при RGB порогах 6/9 даёт native ~86,7 pt, Safari r1 ~83,3 pt. Шаг ~2/3 pt, HEVC и слабая кромка дают неопределённость. Пик r1 позднее, held native ~74 pt, r1 ~72,7 pt. Это не субпиксельный контур. При извлечении выбранных кадров FFmpeg нужны -fps_mode passthrough и проверка количества; иначе он дублирует выбранные кадры по синтетическому fps Annex-B.

r2: высотная фаза ×1,13, амплитуда ×1,15, оптическая добавка 1,2 pt по полной высоте активной линзы; свечение панели .73 вместо .6, дисперсия иконок .65 pt по нормали и спектральные блики на пересечении капсулы с верхом/низом панели. В покое эффекты отсутствуют. Отдельная задержка .025 с центра при старте из покоя — относительная фаза native, не перенос transport latency. Проверить новой записью. Временный test/dev/motion-v124-bank.html содержит полный сайт с новым меню и диагностикой, убрать дубль после принятия.

Свежий PNG работает через pymobiledevice3 developer dvt screenshot --userspace --udid DEVICE OUT.png: текущая вкладка Safari подтверждена, 1206×2622, ICC/EXIF сохранены. Не заменять его старыми устаревшими снимками devicectl.

## Проверка r2 и эксперимент r3

r2: 2303 кадра длинных входов, потерь RTP/AU нет. Видимая высота по тому же методу: пик 86,0 pt против native 86,7; steady около 74 pt. Шаг ~2/3 pt, не субпиксельная оценка. Привязывать фазу к видимому началу реакции, не host dispatch: абсолютная задержка между сериями меняется на десятки мс. Относительно первого изменения яркости панели пик r2 отличается примерно на кадр 60 fps. Это опорный контрастный признак, не точное время touch processing.

Полный банк r2 проверен на физическом Safari: четыре страницы, удержание, rapid retarget, прокрутка и изменение toolbar, errors=0, glass on. Временная полная QA-страница всё ещё отдельно от production v123.

Получены PNG удержанного native Glass через DVT. В fixtures сохранены только обезличенные crops меню с ICC: native-glass-rest.png/native-glass-hold.png, metadata native-glass-reference.json. Crop [0,2340,1206,261] из 1206×2622. Native текст «Поддержка» в hold около 212×33 px против rest 175×27; r2 около 204×31 против 175×26, поэтому r3 проверяет mag=1.14. Сравнивать PNG с корректным преобразованием ICC; RGB HEVC и PNG не считать одним цветовым пространством без проверки.

r3 добавляет эксперимент GLS.cut: отдельные существующие слои (не родитель backdrop!) клипируются compound nonzero path: full plane − lens + inward bar (W−8pk,H−6pk). Внутри линзы появляется живая страница на узкой преломлённой полосе, вместо всегда прямой непреломлённой панели. Все слои используют общий SVG path и статические translated clipPath/use, d меняется один раз/кадр. GLOW ограничен внутренней панелью, внешняя граница/дисперсия отдельные. В покое все clipPath очищаются; статическая карта RIM не меняется. Это гипотеза для измеренной полосы, не точный shader Apple; проверить корректность Safari, фон, fps и Q до принятия. Если тест провалится — откатить эксперимент или исправить, не публиковать в корне автоматически.

Короткий drag/release теперь сохраняет minimum pressure phase .23 с от оригинального down, даже после retarget. Новые генератор профилей и compare_motion_model.cjs читают собственно production functions; числа сравнения virtual после физической фазовой калибровки не равны ранним RMS r1. Исходные профили регенерируются точно.

capture_png_burst.py — bounded PNG sequence, existing pairing only, no settings/install/audio. Burst DVT может останавливать RTP на несколько секунд; использовать для неподвижных состояний, не для доказательства уникальных кадров/темпа. После burst выбирать проверенный steady кадр и удалять лишние собственные временные снимки. Полные экраны/телефонные данные не публиковать.
